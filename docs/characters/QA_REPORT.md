## 2. 실제 구현 범위

12 World / 20 Species / 3단계의 기존 60개 Character ID에 새 벡터 아트와 표시 이름을 연결했다. runtime `renderMonsterSvg`와 배포 SVG는 같은 정의를 사용한다. 20종마다 별도 형태를 가지며 진화별 비율·장식·자세·소품 변화가 있다. 이름 대응표는 `name-map.json`, 전체 ID/노출 화면 대응은 `inventory.json`에 있다.

기존 아바타 56개 아이템과 10개 저장 슬롯을 공통 SVG로 렌더링한다. 홈·프로필·DOM 미리보기·Phaser 드레스룸·상점 미리보기·PNG 내보내기가 같은 착장 정의를 사용한다. 기존 Pet 5종, 장식 18종도 새 작화로 연결했다. 별도 1,000종 XP 컬렉션은 20개 생성형 계열을 개선했으며 60개 단위로 페이지를 나누어 #1000까지 접근한다. 1,000개를 각각 수작업으로 그렸다는 의미가 아니다.

생성된 배포 SVG는 199개다: Season 2 60개, 이전 아바타 레이어 40개, 아이템 미리보기 56개, Pet 5개, 장식 18개, XP 계열 20개. 별도로 새 환경 일러스트 `assets/art/word-garden.svg`를 사용한다. 기존 래스터 그림은 다른 참조의 호환성을 위해 제거하지 않았다.

도감 상세에 성격·행동 설정·실제 친밀도·진화 조건·기록에서 확인 가능한 획득일을 연결했다. 날짜가 없으면 `기록 없음`이다. 파트너의 정답/재도전 반응, 실제 저장이 성공한 뒤의 진화와 부화 공개 연출을 연결했다. 가격·보상·확률·진화 비용과 스키마는 바꾸지 않았다.

## 4. 전후 측정

다음은 run 34002447689에서 실제 기록한 단일 CI 표본이다. 새 기기/통신 환경의 성능 보장이나 통계적 평균/p95가 아니다. `readyMs`는 앱 준비를 확인한 시점의 performance.now()로, FCP/LCP가 아니다. 전송량은 준비 이후 같은 origin의 ResourceTiming encodedBodySize 합이며 TLS/HTTP 헤더나 외부 CDN을 포함하지 않는다.

| 390 | 317.9 → 315.6 ms | 745,848 → 632,290 bytes | 85 → 34 ms |
| 320 | 306.2 → 333.8 ms | 745,848 → 632,290 bytes | 85 → 34 ms |

첫 화면 전송량은 이 표본에서 약 15% 줄었고, XP 도감의 동시 DOM 카드 수는 1,000→60으로 줄었다. 좁은 화면의 홈 준비는 오히려 27.6ms 늘었다. 이 결과를 모든 화면이 빨라졌다는 주장으로 해석하지 않는다. 여러 번의 실기기 부하/스크롤 프레임 테스트와 사전 수치 성능 예산의 통계적 검증은 하지 않았다. 측정 후 기준을 소급해 만들지 않는다.

## 5. 실제 이미지 검수와 수정

전체 60개 contact sheet, 20종의 1단계 실루엣, 20종 진화 3단계 비교판, 56개 아이템판, 64/128/256px 대표 아트를 생성하고 이미지를 직접 열어 확인했다. 전후 대표는 쿠키곰/기어로봇/화산용이다. 모든 캐릭터가 새 정의를 쓰는지는 카탈로그/정적 출력 검사로 교차 확인했다.

Home/Profile/Dress/Shop/Pet/도감/상세/진화/정답/오답/완료/희귀·전설 공개 화면을 캡처했다. Desktop/Mobile의 상세·진화·학습·공개 상태도 별도 파일로 남겼다.

검수에서 발견하고 고친 문제:

1. 모바일 홈 말풍선 아래의 캐릭터가 문구에 겹침: 세로 flex 공간을 분리했다. 390/320에서 문구 아래 8px 이후부터 아트가 시작함을 치수로 확인했다.
2. 드레스룸 발끝 잘림: 원본 360×460 캔버스는 전신이었으나 legacy grid의 intrinsic sizing 때문에 390px에서 표시 캔버스 높이가 375.66px, 호스트 높이는 316px였다. canvas를 absolute로 제한하고 object-fit으로 전체를 유지했다. 최종 390px 캔버스와 호스트는 모두 294×316, 320px에서는 모두 224×316이다. 원본 PNG와 실제 화면을 각각 다시 열어 발끝까지 보이는지 확인했다.
3. Phaser 실패 폴백의 크기/상태 문구 중첩: 폴백 영역과 상태 안내 위치를 분리해 전체 착장을 유지했다.
4. 60개 비교판 마지막 행의 이름 잘림: 고정 캡처 높이 대신 렌더링된 마지막 카드 위치로 높이를 산출한다. 전체 카드 수와 마지막 행의 이름까지 화면 안에 들어오는지 별도 assertion을 추가했다.

초기 실패를 숨기거나 기준을 낮추지 않았다. run 34002181234는 위 캔버스 초과를 검출하여 실패했고, 수정 후 34002447689에서 같은 검사가 통과했다.

## 6. 자료 경로와 재현

Artifact의 `before/`와 `after/`에 전후 화면 및 `browser-report.json`, `geometry/`에 크기별 canvas/실화면/viewport-report.json이 있다. `after/all-60.png`, `after/silhouettes-20.png`, `after/species-evolutions-20.png`, `after/all-avatar-items-56.png`가 전체 아트 비교판이다.

로컬에 Node와 Chrome이 있으면:

```sh
npm run generate:assets
npm run check
python3 -m http.server 4173 --bind 127.0.0.1
# 별도 터미널에서
BASE_URL=http://127.0.0.1:4173 CHARACTER_QA_OUTPUT=./audit/characters node tools/character-integration-qa.mjs
BASE_URL=http://127.0.0.1:4173 CHARACTER_QA_OUTPUT=./audit/geometry node tools/character-viewport-audit.mjs
```

Windows에서는 환경변수 지정 문법을 사용하는 셸에 맞춘다. 기본 Chrome 명령은 google-chrome이며 통합 검사에서는 CHROME_PATH를 지정할 수 있다. 저장소의 `Character browser review` workflow가 기준선 서버, 글꼴과 artifact를 포함한 재현 경로다.

## 7. 배포 및 남은 경계

이 기록 시점에는 작업 브랜치와 PR에만 반영했다. main 병합·GitHub Pages 운영 배포는 수행하지 않았다. 브랜치 보호나 필수 검사를 우회하지 않았다.

실제 Android/iOS/WebKit, 저성능 실기기의 장시간 스크롤·애니메이션, 운영 Firebase end-to-end, 사용자/아동 대상 반응 조사는 미실행이다. 기존 장착 조합 전체의 조합론적 전수 시각 검수도 하지 않았으며 모든 개별 아이템판과 대표 착장/겹침 규칙을 확인했다. SVG 제작 원본과 화면용 배포 파일은 준비했지만 인쇄 색분해·봉제 패턴·상품화 권리 조사까지 완료한 것은 아니다.
